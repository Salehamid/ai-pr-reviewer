# AI-Powered Automated PR Reviewer — workshop starter

TypeScript + Gemini API + GitHub REST API + GitHub Actions. Works as **one PR timeline comment**, not line-by-line diff comments. The reviewer **does not change or execute PR code**.

## Prerequisites
- Node.js 22+, Git, GitHub repository with Actions enabled.
- A Google AI Studio API key with access to `gemini-3.5-flash` or an equivalent available free-tier model.
- Use dummy/public test code only if using Gemini free tier; review the provider's data-use policy.

## Local demo
```bash
npm install
cp .env.example .env  # Windows PowerShell: Copy-Item .env.example .env
# Edit .env and set GEMINI_API_KEY, GEMINI_MODEL
npm run check
npm run demo
```

## GitHub integration
1. Commit the entire project (including `package-lock.json` generated by npm install) to the default branch of a fresh training repository.
2. Repository Settings -> Secrets and variables -> Actions -> New repository secret -> `GEMINI_API_KEY`.
3. Repository Settings -> Actions -> General -> Workflow permissions: allow read/write as appropriate to organization policy. The job explicitly asks for `issues: write` to comment on PRs.
4. Create a **new branch inside the same repository**, add/change a sample `.ts` file, commit, push, create a pull request into the default branch.
5. Check Actions -> AI Pull Request Review; then open the PR's Conversation tab and see the bot comment.
6. Push a further commit: it updates the bot's existing comment instead of duplicating it.

## Manual review on a PR (local)
Configure `.env` with GITHUB_TOKEN (fine-grained token granting permission to read pull requests + write issues), GITHUB_REPOSITORY=owner/repo, PR_NUMBER=number, GEMINI_API_KEY, DRY_RUN=true. Then `npm run review` for preview. Set DRY_RUN=false to post/comment only when intentional.

## Important security limits
- Workflow uses `pull_request_target` but NEVER checks out or executes PR-head code. The checkout points explicitly to the trusted default branch.
- Fork PRs are excluded; do not remove guard casually. If supporting forks, design a separate low-privilege workflow/approval architecture.
- PR content can contain prompt injections; treated as untrusted input. Do not follow model output as executable commands.
- This training code only reviews at most 25 files and 40k characters of patches, supports selected text extensions, and silently omits binary/oversize individual patches.
- PRs that include changes to the workflow file do not change the running trusted workflow code until reviewed/merged to the base branch.
- GitHub default branch changes and malicious repository collaborators are outside this teaching prototype's threat model; use branch protection/codeowners in real deployments.
- The Gemini API is a hosted service. Free-tier code may be used by the provider to improve products. Avoid company secrets.
- Review findings are hypotheses, not guaranteed facts. Always require human review.
- Verify GitHub permissions, Gemini quotas and provider API changes before the workshop.
